## 1. Project Overview

**EAMSagemCom** is a full-stack **Enterprise Asset Management (EAM)** web application built for Sagemcom. It is an academic project designed to be demonstrated to a university tutor.

- **Backend:** Python / FastAPI, SQLAlchemy (PostgreSQL), Celery, MinIO, SSE notifications
- **Frontend:** React + TypeScript + Vite, TailwindCSS-like (plain CSS), ShadCN UI components
- **ML Engine:** scikit-learn (Random Forest), pandas, numpy — for Predictive Maintenance

### How to Run

```bash
# Backend
cd app/backend
./venv/Scripts/activate
uvicorn main:app --reload

# Frontend
cd app/frontend
npm run dev
```

## 4. What Was Done Before This Handoff

### ✅ Phase 1 — Machine Health Score
- `healthScore.ts` computes a score 0–100 based on maintenance history, open work orders, and machine status.
- `MachineHealthBar.tsx` and `MachineHealthPanel.tsx` display this.
- Used in all machine grids (Admin, ChefTech, Chetop).

### ✅ Phase 2 — Reliability Metrics (MTTR, MTBF, Uptime)
- `reliabilityMetrics.ts` computes all reliability KPIs from intervention history.
- `ReliabilityTab.tsx` shows per-machine reliability (inside Machine Detail).
- `ReliabilityDashboardTab.tsx` shows fleet-wide reliability on dashboards.

### ✅ Phase 3 — QR Code Generation
- `MachineQRCode.tsx` generates downloadable QR codes for each machine.

### ✅ Phase 4 — Notifications (SSE)
- `core/notifications.py` broadcasts real-time events via `/api/v1/notifications/stream`.
- Frontend `Header.tsx` and `TechnicianLayout.tsx` consume this SSE stream.

### ✅ Phase 5 — Machine Learning Integration (Baseline)
- Backend: `ml_predictive.py` uses linear regression on intervention history to estimate RUL (Remaining Useful Life).
- API endpoint: `GET /api/v1/ml/machines/{machine_id}/prediction` returns `{ rul_days, risk_level, failure_probability, predicted_failure_date }`.
- Frontend: `PredictivePanel.tsx` calls this endpoint and renders the prediction UI.

### ✅ Phase 6 — Machine Detail Refactoring
- Merged `ChefTechMachineDetail.tsx` and `TechnicianMachineDetail.tsx` into one shared `MachineDetailPage.tsx`.
- Role-based conditional rendering is done via `useAuth()` hook checking `user.role`.
- Updated `AppRoutes.tsx`: both `/machines/:id` and `/technician/machines/:id` now point to `MachineDetailPage`.
- **⚠️ Known issue:** The build may still have a minor TypeScript/import warning. All critical import paths from `cheftech/machines` have been updated to `shared/machines`. Run `npm run build` and check for any remaining errors.

### ✅ Phase 7 — ML Research & Training (Kaggle)
- Dataset: `ai4i2020.csv` (AI4I 2020 Predictive Maintenance — 10,000 rows).
- Trained a `RandomForestClassifier` achieving **98% accuracy, 63% recall on failures**.
- Saved as **`basic_machine_model.pkl`** in the project root.
- CLI demo: `python predict_cli.py --air 301.5 --process 311.0 --rpm 1450 --torque 55.0 --wear 200`

## 8. Dataset Fields Reference (AI4I 2020)

| Column | Description | Role in Model |
|:---|:---|:---|
| `Air temperature [K]` | Ambient temperature | Feature |
| `Process temperature [K]` | Machine operating temp | Feature |
| `Rotational speed [rpm]` | Motor speed | Feature |
| `Torque [Nm]` | Mechanical torque | Feature |
| `Tool wear [min]` | Cumulative tool usage | Feature |
| `Machine failure` | 0=Healthy, 1=Failed | **Target** |
| `TWF` | Tool Wear Failure | Sub-label |
| `HDF` | Heat Dissipation Failure (top predictor) | Sub-label |
| `PWF` | Power Failure | Sub-label |
| `OSF` | Overstrain Failure | Sub-label |
| `RNF` | Random Failure | Sub-label |

**Key insight for the tutor presentation:** Heat Dissipation (`HDF`) has the strongest correlation (57%) with machine failure. This validates the decision to monitor temperature as the primary predictive signal.
