# Phase 12.1: RAG Implementation — Context

**Gathered:** 2026-05-11
**Status:** Ready for planning
**Source:** Engineering session decisions

<domain>
## Phase Boundary

Build targeted RAG pipeline for EAM unstructured documents (maintenance manuals, SOPs, intervention reports).
Wire semantic retrieval into existing `/api/v1/chat/ai/chat` endpoint.
Add document upload and management API.

**NOT in scope:** RAG for structured data (work orders, machines, alerts) — SQL tool calling handles those perfectly.

</domain>

<decisions>
## Implementation Decisions

### Vector Store
- Use pgvector extension on existing PostgreSQL — zero new infrastructure
- Raw pgvector SQL queries — NO LlamaIndex (simpler, fewer deps, more control)
- Similarity metric: cosine distance (`<=>` operator)
- Threshold: 0.7 similarity minimum to inject context

### Embedding Model
- `sentence-transformers/all-MiniLM-L6-v2` — 384 dimensions
- Runs in container, ~80MB, free, no API calls
- Embed at ingestion time, embed query at retrieval time

### Document Ingestion
- PDF support via PyMuPDF (`fitz`) — lightweight, no Java
- Plain text (.txt) support
- No LlamaIndex — direct chunking logic

### Chunking Strategy
- Recursive chunking: 512 tokens, 50 token overlap
- Sentence-aware (don't split mid-sentence)

### Data Model
- Two tables: `documents` (metadata) + `doc_chunks` (content + embeddings)
- `documents.machine_id` FK nullable — link doc to specific machine if known
- `doc_chunks.metadata JSONB` — stores page number, section, doc_type, machine_id
- Machine linkage enables filtered retrieval: "give me chunks for machine 42 only"

### Retrieval
- Top-3 chunks by cosine similarity
- Optional `machine_id` filter in WHERE clause
- Inject as `[CONTEXTE DOCUMENTAIRE]` section in system prompt
- Only inject if at least 1 chunk above threshold — don't pollute prompt with irrelevant context

### Chat Integration
- `/chat/ai/chat` — before Groq call: embed query → retrieve chunks → augment system prompt
- `/chat/analyze` — same retrieval, same injection
- Retrieval is additive — doesn't replace tool calling, runs alongside it

### Upload API
- `POST /api/v1/rag/documents` — multipart file upload (PDF or TXT)
- Fields: file, doc_type (manual|sop|report), machine_id (optional), description
- Trigger ingestion pipeline synchronously (files are small, async overkill for now)
- `GET /api/v1/rag/documents` — list documents
- `DELETE /api/v1/rag/documents/{id}` — delete doc + all its chunks

### No Real Docs Available
- No actual machine manuals exist yet — build pipeline ready to accept them
- Include test fixture: simple synthetic text doc for integration testing

### New Dependencies
- `pgvector>=0.3.0` — SQLAlchemy vector column type
- `sentence-transformers>=3.0.0` — embedding model
- `pymupdf>=1.24.0` — PDF extraction
- Add to `requirements.txt`, rebuild Docker image

### Migration Strategy
- New Alembic migration: `add_pgvector_rag`
- Enable `vector` extension (`CREATE EXTENSION IF NOT EXISTS vector`)
- Create `documents` table then `doc_chunks` with `vector(384)` column
- Create ivfflat index on `doc_chunks.embedding` for ANN search
- Down_revision: `add_chat_sessions` (current head)

</decisions>

<specifics>
## Specific Implementation Details

### Similarity query (raw pgvector):
```sql
SELECT dc.content, dc.metadata,
       1 - (dc.embedding <=> :query_vec) AS similarity
FROM doc_chunks dc
WHERE (:machine_id IS NULL OR dc.metadata->>'machine_id' = :machine_id)
  AND 1 - (dc.embedding <=> :query_vec) > 0.7
ORDER BY dc.embedding <=> :query_vec
LIMIT 3;
```

### System prompt injection format:
```
[CONTEXTE DOCUMENTAIRE]
Source: Manuel machine M-42 (page 3)
Contenu: ...chunk text...

Source: SOP-07 Procedure d'arret d'urgence
Contenu: ...chunk text...
[FIN CONTEXTE]
```

### Existing files to integrate with:
- `services/ai_prompts.py` — add `build_rag_context(chunks)` function
- `modules/shared/routes/chat.py` — call retriever before Groq in `ai_chat` and `analyze`
- `models/__init__.py` — register new models
- `app/backend/requirements.txt` — add 3 new deps

</specifics>

<deferred>
## Deferred

- Async ingestion queue (Celery) — sync is fine for now, files are small
- Re-ranking (cross-encoder) — cosine similarity sufficient for phase 1
- Hybrid search (BM25 + vector) — pure vector search first
- Multi-language embeddings — French docs only for now, MiniLM handles it
- Chunk-level access control — all authenticated users see all docs for now
- Document versioning — simple delete + re-upload for updates

</deferred>
