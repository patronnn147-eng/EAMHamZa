## Summary

RAG pipeline for EAM: document upload → PDF/text extraction → recursive chunking → sentence-transformer embedding → pgvector storage → cosine similarity retrieval → system prompt augmentation.

Stack is pure Python, no external services. pgvector extension runs inside existing Postgres container. `sentence-transformers` loads model once at startup as singleton. `pymupdf` extracts text from PDFs with page metadata.

**Primary recommendation:** Load embedding model as module-level singleton at import time. Use `pgvector` SQLAlchemy type for vector column. Use raw `text()` SQL for similarity queries (SQLAlchemy ORM doesn't support `<=>` operator natively).

### Pattern 1: Embedding Model Singleton
Load once at module import. SentenceTransformer is ~300ms cold start — unacceptable per-request.
```python
# services/rag_embedder.py
from sentence_transformers import SentenceTransformer
import numpy as np

_model: SentenceTransformer | None = None

def get_embedder() -> SentenceTransformer:
    global _model
    if _model is None:
        _model = SentenceTransformer("sentence-transformers/all-MiniLM-L6-v2")
    return _model

def embed_text(text: str) -> list[float]:
    model = get_embedder()
    vector = model.encode(text, normalize_embeddings=True)
    return vector.tolist()

def embed_batch(texts: list[str]) -> list[list[float]]:
    model = get_embedder()
    vectors = model.encode(texts, normalize_embeddings=True, batch_size=32)
    return vectors.tolist()
```

### Pattern 2: pgvector SQLAlchemy Column

# models/documents.py
from pgvector.sqlalchemy import Vector

import uuid

class DocChunk(Base):

    doc_id = Column(UUID(as_uuid=True), ForeignKey("documents.id", ondelete="CASCADE"))

### Pattern 3: Raw SQL Cosine Similarity (required — ORM can't express `<=>`)
```python
# services/rag_retriever.py
from sqlalchemy import text
from sqlalchemy.ext.asyncio import AsyncSession

async def retrieve_chunks(
    query: str,
    db: AsyncSession,
    machine_id: int | None = None,
    top_k: int = 3,
    threshold: float = 0.7,
) -> list[dict]:
    query_vec = embed_text(query)

    sql = text("""
        SELECT dc.content, dc.metadata,
               1 - (dc.embedding <=> CAST(:vec AS vector)) AS similarity
        FROM doc_chunks dc
        JOIN documents d ON dc.doc_id = d.id
        WHERE (:machine_id::int IS NULL OR (d.machine_id = :machine_id))
          AND 1 - (dc.embedding <=> CAST(:vec AS vector)) > :threshold
        ORDER BY dc.embedding <=> CAST(:vec AS vector)
        LIMIT :top_k
    """)

    result = await db.execute(sql, {
        "vec": str(query_vec),
        "machine_id": machine_id,
        "threshold": threshold,
        "top_k": top_k,
    })
    rows = result.fetchall()
    return [
        {"content": r.content, "metadata": r.metadata, "similarity": r.similarity}
        for r in rows
    ]
```

### Pattern 4: Recursive Text Chunking (no LlamaIndex)
```python
def chunk_text(text: str, chunk_size: int = 512, overlap: int = 50) -> list[str]:
    """Sentence-aware recursive chunking."""
    import re
    # Split on sentence boundaries first
    sentences = re.split(r'(?<=[.!?])\s+', text)
    chunks, current, current_len = [], [], 0

    for sentence in sentences:
        words = sentence.split()
        if current_len + len(words) > chunk_size and current:
            chunks.append(" ".join(current))
            # Keep overlap words from end of current chunk
            overlap_words = current[-overlap:] if len(current) > overlap else current
            current = overlap_words + words
            current_len = len(current)
        else:
            current.extend(words)
            current_len += len(words)

    if current:
        chunks.append(" ".join(current))
    return [c for c in chunks if len(c.strip()) > 20]  # filter empty/tiny chunks
```

### Pattern 5: pgvector Migration
```python
# MUST use sync op.execute() for CREATE EXTENSION — Alembic doesn't support async here
def upgrade():
    op.execute("CREATE EXTENSION IF NOT EXISTS vector")
    op.create_table("documents", ...)
    op.create_table("doc_chunks", ...)
    # ivfflat index — faster for cosine, good up to ~1M vectors
    op.execute("""
        CREATE INDEX IF NOT EXISTS ix_doc_chunks_embedding
        ON doc_chunks USING ivfflat (embedding vector_cosine_ops)
        WITH (lists = 100)
    """)
```

### Pattern 6: Context Injection Format
```python
def build_rag_context(chunks: list[dict]) -> str:
    if not chunks:
        return ""
    lines = ["\n\n[CONTEXTE DOCUMENTAIRE]"]
    for chunk in chunks:
        meta = chunk.get("metadata", {})
        source = meta.get("filename", "Document")
        page = meta.get("page")
        page_str = f" (page {page})" if page else ""
        sim = chunk.get("similarity", 0)
        lines.append(f"\nSource: {source}{page_str} (similarite: {sim:.0%})")
        lines.append(f"Contenu: {chunk['content'][:800]}")
    lines.append("\n[FIN CONTEXTE DOCUMENTAIRE]")
    return "\n".join(lines)
```

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Vector similarity | Custom dot-product | pgvector `<=>` | Handles normalization, indexing, ACID |
| PDF text extraction | PyPDF / pdfminer | pymupdf (fitz) | 5-10x faster, handles malformed PDFs |
| Sentence embeddings | Custom transformer | all-MiniLM-L6-v2 | Pre-trained, 384-dim, French OK |
| Chunking | Token-count split | Sentence-aware split | Mid-sentence splits kill retrieval quality |

## Common Pitfalls

### Pitfall 1: Sync embed call inside async route
**What goes wrong:** SentenceTransformer.encode() is sync — blocks async event loop
**Prevention:** Run in thread pool executor
```python
import asyncio
loop = asyncio.get_event_loop()
vector = await loop.run_in_executor(None, embed_text, query)
```

### Pitfall 2: pgvector extension not enabled before table creation
**What goes wrong:** `CREATE TABLE doc_chunks (embedding vector(384))` fails with "type vector does not exist"
**Prevention:** `CREATE EXTENSION IF NOT EXISTS vector` MUST be first statement in migration upgrade()

### Pitfall 3: Vector casting in asyncpg
**What goes wrong:** asyncpg doesn't know how to serialize Python list → postgres vector type
**Prevention:** Cast explicitly in SQL: `CAST(:vec AS vector)` where `:vec` is the string representation `[0.1, 0.2, ...]`
```python
vec_str = "[" + ",".join(str(x) for x in vector) + "]"
```

### Pitfall 4: ivfflat index requires data before creation
**What goes wrong:** `CREATE INDEX USING ivfflat` on empty table gives poor `lists` estimation
**Prevention:** Create with `lists = 100` regardless — fine for < 1M vectors. Index auto-updates on insert.

### Pitfall 5: Large model download on container startup
**What goes wrong:** First container start downloads all-MiniLM-L6-v2 (~80MB) — slow CI, timeout healthchecks
**Prevention:** Pre-download in Dockerfile
```dockerfile
RUN python -c "from sentence_transformers import SentenceTransformer; SentenceTransformer('sentence-transformers/all-MiniLM-L6-v2')"
```

### Pitfall 6: Memory spike during batch embedding
**What goes wrong:** Embedding 100-page PDF all at once → OOM
**Prevention:** Process chunks in batches of 32, not all at once

### Pitfall 7: pymupdf import name mismatch
**What goes wrong:** `import pymupdf` fails — package installs as `fitz`
**Prevention:** `import fitz` (the internal module name), not `import pymupdf`

## Code Examples

### Full ingestion pipeline
```python
async def ingest_document(
    file_bytes: bytes,
    filename: str,
    doc_type: str,
    machine_id: int | None,
    db: AsyncSession,
) -> Document:
    # 1. Extract text
    if filename.endswith(".pdf"):
        text_pages = extract_pdf_text(file_bytes)  # returns list[(page_num, text)]
    else:
        text_pages = [(1, file_bytes.decode("utf-8", errors="ignore"))]

    # 2. Create document record
    doc = Document(filename=filename, doc_type=doc_type, machine_id=machine_id)
    db.add(doc)
    await db.flush()  # get doc.id

    # 3. Chunk all pages
    all_chunks = []
    for page_num, page_text in text_pages:
        for chunk_idx, chunk in enumerate(chunk_text(page_text)):
            all_chunks.append((chunk, {"page": page_num, "filename": filename,
                                       "doc_type": doc_type, "machine_id": machine_id}))

    # 4. Embed in batches
    texts = [c[0] for c in all_chunks]
    vectors = embed_batch(texts)  # list of list[float]

    # 5. Store chunks
    for (chunk_text_, meta), vector in zip(all_chunks, vectors):
        vec_str = "[" + ",".join(f"{x:.6f}" for x in vector) + "]"
        db.add(DocChunk(
            doc_id=doc.id,
            chunk_index=len(db.new),
            content=chunk_text_,
            embedding=vec_str,
            metadata_=meta,
        ))

    await db.commit()
    return doc
```

### PDF extraction with page tracking
```python
import fitz  # pymupdf

def extract_pdf_text(file_bytes: bytes) -> list[tuple[int, str]]:
    pages = []
    with fitz.open(stream=file_bytes, filetype="pdf") as pdf:
        for page_num, page in enumerate(pdf, start=1):
            text = page.get_text("text").strip()
            if text:  # skip blank pages
                pages.append((page_num, text))
    return pages
```

## Open Questions

1. **Thread pool for sync embed — how many workers?**
   - Recommendation: Use default (`None` = CPU count). MiniLM is CPU-bound, not worth tuning.

2. **Max file size for upload?**
   - Recommendation: 50MB limit. FastAPI multipart handles this with `UploadFile`.

3. **ivfflat lists parameter?**
   - Recommendation: `lists = 100`. Good for up to ~1M vectors. Revisit if collection grows.
